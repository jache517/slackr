# Visible Adoption, Untracked Contribution: GitHub Evidence of the Accountability Gap Across Three Cohorts of an HCI Prototyping Course

**Authors:** Maria Teresa Parreira, Pranav Prabhat Sinha, Hauke Sandhaus, Wendy Ju (Cornell University / Cornell Tech)
**Date:** arXiv listing June 2026 (arXiv:2606.14054); workshop position paper, grounding a CHIWORK '26 adjunct workshop discussion ("Interrogating GenAI augmentation for CHIworkers")
**Source:** [arXiv:2606.14054](https://arxiv.org/abs/2606.14054) (HTML: https://arxiv.org/html/2606.14054). Data and analysis code: https://github.com/IRL-CT/idd-x-ai
**Relevance to Slackr:** Directly on-topic and a new angle not yet in this folder. This is a large-scale, three-cohort (66/55/82 repos, 203 total, 23,065 student commits) computational analysis of exactly the kind of GitHub evidence Slackr's own MVP is built to collect (commits, READMEs, file-type mix, commit timing), and it finds that the evidence trail itself becomes structurally less trustworthy as AI-assisted coding becomes ambient. This is the strongest available caution against treating raw GitHub activity as self-evidently attributable to a named human contributor.

## Summary

The authors run a longitudinal, observational case study of the same graduate HCI prototyping course at Cornell Tech across three cohorts spanning the GenAI transition: Fall 2022 (pre-AI, no major tools in wide use), Fall 2023 (early-AI, ChatGPT newly available), and Fall 2025 (vibe-AI, AI tools embedded directly in the course's GitHub template). Course structure, assignments, and the disclosure policy ("cite what you use") stayed fixed across all three years, so differences across cohorts more plausibly reflect the surrounding AI environment than changes to the course itself. They mine all forked repositories via the GitHub API, filter to 203 active repositories and 23,065 student commits (excluding instructors and bots, restricting to the semester window), and distinguish two levels of "accountability trace": disclosure (naming an AI tool at all, typically in a README) and attribution (a sentence that credits a specific artifact or task to that tool, e.g. "the motor code was written with ChatGPT"). They report five findings (F1-F5) using Mann-Whitney U tests with Bonferroni correction and rank-biserial effect sizes.

## Key Findings

- F1 - AI adoption grew monotonically and diversified: the share of repositories naming an AI tool in their README rose from 0% (pre-AI) to 36% (early-AI) to 66% (vibe-AI), all pairwise differences highly significant (p < 0.001, large effects), with the median number of distinct tools named rising from 0 to 2 to 8.
- F2 - naming a tool is not the same as attributing a contribution: only 0% / 23% / 42% of repositories (pre/early/vibe) contained a sentence that actually credited specific work to a named AI tool, versus the much higher 66% disclosure rate in vibe-AI. The gap between F1 (66%) and F2 (42%) is, in the authors' words, "the accountability gap within the designated disclosure surface itself."
- F3 - commit frequency rose with AI adoption but the cause is undecidable from the log alone: vibe-AI averaged 49 commits per person versus 31 (early-AI) and 26 (pre-AI), p < 0.001, large effect. The paper is explicit that this is "consistent with, but not proof of" AI-agent involvement, since an agent committing under a student's identity looks identical in the log to a human genuinely iterating faster.
- F4 - the type of work committed shifted from assets to code: median code-file-change share rose from 13% (pre-AI) to 44% (vibe-AI), p < 0.001, large effect, even though the underlying lab assignments were unchanged year to year.
- F5 - code and writing style diverged in vibe-AI: inline comment density fell (15.6% to 12.8%) while docstring density rose (2.3% to 3.9%), a pattern the authors attribute to LLMs reliably generating structured docstrings while omitting the informal inline comments typical of a novice working from a tutorial. A separate LLM-vocabulary marker in README text step-changed between pre-AI and early-AI, then plateaued into vibe-AI, which the authors flag as likely reflecting that by 2025 models had been tuned to avoid the very phrasing the detector was calibrated on, not that AI use had leveled off.
- The authors explicitly checked commits for machine-authored attribution metadata (Co-Authored-By trailers from tools like Claude Code or GitHub Copilot) and found none in any cohort, in any repository: "where AI involvement appears at all, it is expressed in prose rather than in structured commit metadata."
- By Fall 2025, AI tooling (Copilot chat modes, instruction files) was pre-installed in every student's forked repository as course infrastructure before any student opted in, which the authors argue changes the nature of the gap: "the behavioral gap is a student not disclosing a tool they chose to use, whereas the structural gap is AI present by default, so that even a fully compliant student has nothing to 'disclose.'"
- Position taken by the authors: disclosure ("did you document your AI use?") is the wrong question for the vibe-coding era; they argue accountability should instead operate at the level of what the artifact's architecture does with AI and whether the student can explain the reasoning behind their design decisions, since a student who wires a language model into a multi-step reasoning pipeline and a student who pasted a single ChatGPT answer into a commit "look identical if disclosure of use is the only mechanism for accountability."

## Why This Matters for Slackr

- This is the most direct threat model yet found for Slackr's core assumption that GitHub activity (commits, PRs, file changes) is trustworthy, attributable evidence of individual student effort. The paper shows that even in a strict, disclosure-required course, a third of students who name an AI tool never say what it actually did (F1 vs F2 gap), and that raw activity signals Slackr would naturally surface, commit count, code-vs-asset mix, comment density, all shift in ways "consistent with AI involvement but not attributable to it." Evidence Slackr collects automatically can look like more individual contribution while representing less of it.
- The finding that AI Co-Authored-By trailers never appeared in any commit, across three cohorts and three tool generations, is a concrete, citable data point that Slackr cannot rely on commit metadata to flag AI-authored work; if AI attribution appears at all, it will be in free-text prose (a commit message or README sentence), not a structured field a pipeline can parse reliably.
- This strengthens, rather than undercuts, Slackr's "evidence, not verdict" design: the paper's own conclusion is that architecture-level, explainable accountability (can the student explain *why* a decision was made) is what's needed, not more granular automated tracking of *what* was typed. That maps directly onto Slackr's member-context step, giving students space to explain contribution the system can't observe, rather than trying to have the pipeline infer AI-vs-human authorship on its own.
- It adds a fourth, distinct thread to the case built by the papers already in this folder. [[2024-10-contribution-rate-imputation-theory]] shows commit counts don't equal effort even without AI in the picture; this paper shows AI adoption is now actively eroding the little signal commit-based evidence still carried, and that the erosion is structural (AI-as-infrastructure) as much as behavioral (AI-as-choice). Any future Slackr feature that scores or ranks GitHub activity should treat this as a hard caveat, not an edge case: the paper's own repositories are graduate CS/HCI students in 2025, i.e. exactly Slackr's target population.
- Practical takeaway for the MVP: if Slackr ever surfaces "% of code changes" or "commit frequency" per member in its Contribution Report, this paper is grounds to caveat those numbers explicitly as observed activity, not verified individual authorship, consistent with the existing README's "evidence, not verdict" framing, and possibly grounds to add an optional AI-disclosure field to the member-context step, since the paper shows disclosure only happens reliably (66%) when a course explicitly asks for it, and even then attribution (42%) lags well behind.
